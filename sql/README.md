# SQL Editor setup

Use the existing PaySME Supabase project, reference `zvoqrqdnuupdefsuiurt`. This repository does not connect to or change the live database automatically.

1. Run **01_create_voucher_foundation.sql** once, in one complete SQL Editor execution. It creates seven new tables, access policies, helper functions, audit triggers and a public product-picture bucket. If a target name already exists, it stops and rolls back instead of overwriting it.
2. Open **02_enroll_staff.sql**, replace `REPLACE_WITH_YOUR_STAFF_EMAIL` with the email of an existing Supabase Auth account, and run it. The account's existing password is used for portal sign-in. If no account exists, create/invite it under Authentication > Users first. This script never writes to `auth.users` or creates passwords.
3. Run **03_verify_setup.sql**. Expect seven tables with RLS enabled and no anonymous SELECT grants, at least one active admin, and the catalogue image bucket/policies.
4. Run **04_test_staff_permissions.sql** as one complete execution for the optional access smoke test. It creates test records and temporarily changes one staff membership inside a transaction, then rolls back everything. The final result should start with `PASS`. If it fails, report the error; do not treat a failed test as approval to bypass RLS.

No existing PaySME business tables, utilities history, wallets, authentication settings or balances are changed by script 01. No voucher sales or real payment release happen in this phase. Script 02 grants access only to the voucher portal.

## Access

| Role | Suppliers / approval emails | Products and branches | Customers | Staff membership |
| --- | --- | --- | --- | --- |
| Admin | Read, create, edit | Read, create, edit | Read | Trusted SQL/admin operation only |
| Operator | Read | Read, create, edit | Read | None |
| Viewer | Read | Read | Read | None |
| Other signed-in users | None | None | None | Own membership lookup only |
| Anonymous | None | None | None | None |

The public product-picture bucket contains catalogue assets only. It must never contain IDs or other personal documents. Browser users cannot alter customer verification, marketing consent, or audit history.

## Pricing

All monetary values are stored in cents. Supplier base N$500 + PaySME markup N$20 = customer price N$520. With store reference price N$600 the customer saves N$80. Immediate rebates reduce generated `settlement_price_cents`; later rebates do not reduce the current payment obligation. Vendor commission is recorded separately.

The canonical creation SQL is under `supabase/migrations/`. Its numbered SQL Editor copy is regenerated by the build command.
